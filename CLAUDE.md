## Architecture

```
HTTP → generated/routes.ts → Controller (tsoa decorators) → Service (business logic) → Prisma
```

- **Controllers** declare routing, auth, status codes. No business logic. They call `this.setStatus(...)` and pass `request.currentUser` — never the whole request, never a bare `userId`.
- **Services** own all rules and all Prisma access. They receive `currentUser` and re-check role themselves (defense in depth, on top of the tsoa scope check). The banned check lives once in `authentication.ts`, not in services.
- **`src/generated/`** — `routes.ts` and `swagger.json` are build output. Never hand-edit. OpenAPI metadata lives in `apps/api/tsoa.json`.
- **`src/tasks/`** — system work that no persona triggers and no route reaches. `JobExpiryService` is the one example: it takes no `currentUser` and asserts no role, which is exactly why it cannot reuse a `JobManagementService` method (those all open with a role guard). `JobExpiryScheduler` holds the timer; the callback contains no business logic, so the same sweep can later be driven by a script or an endpoint without moving any rules.
- A scheduled/background task is just a second caller of the same Service method; put the logic in a service, not in the timer callback.

## Conventions

- One folder per feature under `api-external/`, containing `XController.ts`, `XService.ts`, and one DTO file per request/response.
- **Filenames mirror the exported symbol**, in PascalCase, whether it is a class, interface, enum, or type — `CompanyResponse.ts` exports `CompanyResponse`, `RoleConstant.ts` exports `RoleConstant`. lowercase is reserved for app wiring that names no domain concept: `app.ts`, `server.ts`, `prisma.ts`, `authentication.ts` (that last one is fixed by `tsoa.json`'s `authenticationModule`). A module of several helpers takes the collection's name (`EmailTemplates.ts`).
- DTO naming: `<Action>Request` / `<Action>Response`; list items are `...Dto` (`MyJobListItemDto`), list endpoints return an envelope (`{ items }`), never a bare array — so pagination can be added without breaking clients.
- List DTOs carry summary fields only; long text (`description`, `requirement`) belongs to the detail DTO.
- A role guard (`assertJobSeeker` / `assertEmployer` / `assertAdmin`) is step 1 of every service method. The shared implementation lives in `api-shared/guard/AssertRole.ts` and every service now uses it — the eight are `EmployerCompanyService`, `JobManagementService`, `EmployerApplicationService`, `ApplicationService`, `ResumeService`, and the three `api-internal` modules (`assertAdmin`). No private copies remain.
- Numbered step comments (`// 1. ...`) in service methods, following `ApplicationService`.
- Errors: `throw new HttpError(status, message)` from `utils/HttpError`.

| Code | Use for |
|---|---|
| 400 | Validation failure, unmet precondition, illegal state transition |
| 401 | Missing / invalid token |
| 403 | Wrong role, banned account, not the owner |
| 404 | Resource does not exist (or must not be revealed to the caller) |
| 409 | Already in the requested state |

Length caps are `400`, not `413`. Ownership checks are 404-then-403.

## Gotchas

- **tsoa validates requests, never responses.** `getValidatedArgs` checks incoming args; the controller's return value is serialized unchecked. A wrong response DTO fails silently at runtime.
- **Excess-property checking only fires on fresh object literals.** `return { items: jobs }` where `jobs` came from `.map()` or Prisma compiles even when the element type has extra fields — and those fields ship in the JSON while `swagger.json` never declares them. Annotate the intermediate (`const items: XDto[] = ...`) when the shape must be exact.
- **Status fields are narrow literals** (`status: "CLOSED"`), so `status: updated.status` will not compile — Prisma returns the whole enum. Write the literal. Keep it narrow: it becomes a real union in the generated client.
- **Prisma nullable → DTO optional**: `Date | null` is not assignable to `Date | undefined`. Convert with `?? undefined`.
- `swagger.json` goes stale whenever DTOs change without a build. Regenerate the API *and* the web client after any contract change.
- `noImplicitAdditionalProperties: "throw-on-extras"` in `tsoa.json` rejects unknown properties on incoming bodies only.

## Known gaps

- **Job expiry is enforced two ways, on purpose.** The four public reads (`JobDiscoveryService.searchJobs` / `.getJobDetail`, `CompanyProfileService`, `ApplicationService.applyJob`) each check `deadline` directly, so UC-EMP-01 holds the instant a deadline lapses rather than whenever a sweep last ran. `JobExpiryService` then writes `status: "EXPIRED"` so the stored value agrees — that is what the Employer list, the moderation screens and `/admin/logs` read from. The sweep touches **only `ACTIVE`**: expiring a `PENDING_APPROVAL` posting would strand it, since a Moderator already cannot approve a lapsed job and `EXPIRED` is not editable, leaving the Employer no way to set a new deadline. `CLOSED` is left alone too, because re-opening already demands a future deadline. Expiry is one-way — restoring a deadline does not bring a posting back; that is `updateJobPosting`'s job.
- `AuditLogger` (in `src/logging/`) now records every mutation across moderation, employer jobs, company, auth, profile, resumes, and applications: each system write and its `Log` row commit in the same interactive `prisma.$transaction`, so a job can't be created with no log (or logged without creating). Standalone events (login) use `logStandalone`. Both former gaps are closed: `logoutUser` is now `@Security("jwt")` so `USER_LOGGED_OUT` has an actor, and UC-ADMIN-05 is live as `AuditLogController` plus `/admin/logs`.

- **Uploaded files are served without authentication — an accepted MVP limitation, not an oversight.** `app.ts` mounts `express.static` at `/uploads` with no auth in front of it, so `ResumeDto.fileUrl` / `EmployerApplicationResponse.resumeFileUrl` / `avatarUrl` are plain paths the browser fetches directly. UC-EMP-06 says an employer may see only the CV attached to that application — a rule the API enforces and the file server does not, so a URL, once seen, keeps working forever and can be forwarded. Closing it means a token-checking download route, which the browser cannot use from `<img src>` or `<a href>` without also changing how the frontend fetches files. Recorded as a scope cut in the use-case document under UC-EMP-06.

  The **write** side of the same code was hardened rather than deferred, because a traversal is a different class of problem from a guessable link: `FileStorageService.safeFileName` now keeps only the last path segment of a client-supplied filename, and `deleteFile` confines its resolved target under `uploads/`. What remains unfixed there: the stored extension still comes from the client rather than the validated MIME type (so a file declared `application/pdf` but named `.html` is served as `text/html` from the API origin), soft-deleted CVs keep their bytes on disk and stay reachable, and a replaced avatar is never unlinked.

## Future work (not urgent)

### Web

- **Date formatting is scattered.** `ui-shared/format/DateFormat.ts` now owns `formatDate` / `formatDeadline` / `isPastDeadline`, pinned to `PLATFORM_TIME_ZONE`. Three older call sites still format inline with their own locale — `ApplicationCard.tsx`, `ResumeSelector.tsx` and `ProfilePage.tsx` (all `en-GB`). Point them at the shared module. (`JobDetailPage` had a fourth, `en-US` and time-zone-blind; it went when the page was wired to the API.)
- **`/profile` only works for a Job Seeker.** `ProfilePage` calls `getMyResumes` and `getJobPreference`, both scoped `["JOB_SEEKER"]`, so an employer or admin opening it gets 403s on two of its sections. The route is still open to any logged-in user, but the employer and admin menus deliberately omit the link. The fix is to split the shared "personal information" part from the Job Seeker-only resume / job-preference parts.
- **`ProfilePage.handleDownload` hardcodes `http://localhost:3000`.** `api/ApiBaseUrl.ts` now exports `API_BASE_URL`, which `apiClient` and `ApplicationDetailPage` use; this is the last hand-written copy.
- **An expired posting now 404s on the public job page.** `getJobDetail` filters on `deadline`, so `GET /jobs/{jobId}` returns 404 once a posting lapses — and `ApplicationCard`'s "View Job" button links straight there. A Job Seeker whose application predates the expiry gets a dead button. UC-JS line 506 only requires the *application* to stay in history, which it does, so this is a UX gap rather than a rule violation: either hide the button for a lapsed job or give the seeker a read-only view.
- **The public pages now read the API; `mockData.ts` is deleted.** `JobDetailPage`, `CompanyProfilePage` and `FeaturedJobs` call `getJobDetail` / `getCompanyProfile` / `searchJobs`, and `ApplyJobPage` no longer accepts a job through router state or falls back to mock rows. Fields the schema never had (stipend, skills, logo, street address, and the Internship/Research/Co-op categories) are gone rather than faked — the landing tabs now filter on `employmentType`, which is the only categorisation `jobs` actually stores, and a company's square shows its first letter via `ui-shared/format/CompanyInitial.ts` because no logo column exists. `hasApplied` went with them: the public detail endpoint returns only postings that are open, so there is no status branch left to render and no unreachable "already applied" state.
- **`ProfilePage` still uses a raw `<textarea>`** — the only one left after the shadcn `Textarea` migration.
- **The employer pages refetch after every mutation.** `MyJobPostingsPage` refetches the whole list, and `MyJobDetailPage` / `ApplicationDetailPage` refetch the single record. Each mutation response already returns the new status and its timestamp, so patching local state would avoid the round trip and the loading blink. Deliberate trade — refetch is always correct, patching duplicates backend rules in the UI.
- **Deadline timezone is the submitting browser's.** `toDeadlineIso` converts using whatever zone the employer's browser was in at submission. UC-EMP-01 says "employer's local time", but no employer timezone is stored — so editing a posting from a different zone changes the instant for the same displayed date.
- **`Hero`'s "popular searches" tags are invented.** "Software Engineering", "Product Design", "AI Research", "Finance", "Data Science" are hardcoded and feed a real keyword search against job titles and company names — so each one returns whatever the database happens to hold, most likely nothing. They are the last placeholder content on the landing page; either point them at terms the seed data actually contains or drop the row.
- **`JobPostingForm` has a stale comment** (`~:114`) justifying the segmented control by claiming `DESIGN.md` forbids adding packages. Rule 2 was rewritten and no longer says that; the real reason is that three mutually exclusive options read better than a dropdown.

### API

- **Dependency direction between `api/` and `ui-shared/auth/`.** `apps/web/src/api/apiClient.ts` imports `clearStoredSession` from `ui-shared/auth/AuthContext.tsx`, so the API layer depends on a React/JSX module. It works and there is no import cycle, but the arrow points the wrong way. Fix by moving the storage keys and `clearStoredSession` into a plain (non-React) `ui-shared/auth/SessionStorage.ts` that both `AuthContext` and `apiClient` import.
- **Package migration: tsoa → `tsoa-next` (do NOT rely on `ignore` for this).** Classic tsoa `7.0.0-alpha.0` resolves every model name reachable from controllers, and `generated/prisma/client.ts` re-exports all Prisma enums (`export * from "./enums"`). Any `api-shared/type/` union whose name matches a Prisma enum can then collide with `Found 2 different model definitions` once tsoa's type-checker symbol resolution sees both declarations (e.g. through `AuditLogger`). `tsoa.json` does accept an `ignore` glob array — but the source shows it only gates *controller* discovery (`metadataGenerator.extractNodeFromProgramSourceFiles`), not the symbol-resolution collision, so it does NOT fix this. That is why `profileVisibility` / `jobSearchStatus` are inlined string literals in `UserDetailResponse.ts` instead of shared type files, while `JobStatus` / `UserStatus` survive as shared files (the collision is not uniformly reproducible). Two sound escape hatches: (a) import the Prisma-generated enum directly in DTOs (`AuditLogListItemDto` does this for `LogAction`/`LogTargetType`/`LogLevel`), which keeps only one declaration in the program; (b) give the shared type a unique name — anything suffixed (e.g. `ApplicationStatusLiteral`) lives in exactly one file, so tsoa keys it by name alone and never collides. `tsoa-next` does not change this picture: its `ignore` option is the same controller-scan gate.
